# Frontend Audit

## Current State

- The repository had no application-grade frontend framework.
- The previous UI was a static HTML status page generated by `scripts/build-site.mjs`.
- Playwright validation already existed, but only for the legacy control-plane surface.
- There was no Storybook, no Penpot source, and no reusable component system.
- The folder `opita-sync-visual-closure` adds useful open assets: teal-first color decisions and the Opita Operational Outline icon family.

## Relevant Product Inputs

- Opita Sync is mobile-first for operational roles.
- Admin tenant and Opita Code flows remain web-first.
- Core user-visible modules are chat, cases, detail views, drafts, reporting, configuration, and governance.
- Billing is out of platform scope, so frontend work should show metering/value evidence rather than invoice UX.

## Free/Open Source Stack Decision

- React + Vite + TypeScript
- Tailwind CSS
- Open-code primitives with shadcn-style composition patterns
- Storybook
- Playwright

## Risks Of Continuity

- Existing QA had to migrate away from the legacy page.
- Mock data is necessary until backend contracts exist.
- A future native app would reuse the system design, not this web code directly.
